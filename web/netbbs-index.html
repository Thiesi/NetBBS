Run a BBS you actually own

A text-based home for your community: message boards, live chat, personal mail, file sharing, and door games on a server you run and moderate. Callers connect through a browser, SSH, or Telnet. Run independently, join other nodes through NetBBS Link, connect chat channels to the MRC network, or carry FidoNet echomail and netmail.

Getting in

A browser or your favorite terminal.

Offer the connection methods your community uses. Browser callers need no additional software; terminal callers use an SSH or Telnet client.

Telnet

The classic path — any telnet client, on the port you choose. Classic terminals such as SyncTERM get their own CP437 character set, and plain-ASCII terminals get plain ASCII.

SSH

Key or password auth over an encrypted channel — the transport most operators reach for by default.

Web

A real terminal in the browser via xterm.js — send a link, they're in. No app, no extension. Try it on ReLink, a live NetBBS node.

New in v7.17 · FidoNet

NetBBS can bark now.

FidoNet's logo is a dog, and its networks have carried conversations between BBSes since 1984. NetBBS now joins FidoNet, fsxNet and other FTN networks as an ordinary node: echomail arrives on your message boards, netmail arrives in Mail, and NetBBS speaks BinkP itself, so there is no separate mailer or tosser to install.

For the SysOp

Everything is set up in the SysOp console, and nothing runs until you create and enable a network.

  • A network in one editor. A new network starts from a template, fsxNet, nixNet or FidoNet, or from a blank draft; add the address and passwords your coordinator gives you.
  • An echo on a message board. Put an echo tag on a message board and ask the hub for more with AreaFix. A message board is local, NetBBS Link or FTN, never two at once.
  • Join from the hub's list. Import the hub's echo list, tick the echoes you want, and NetBBS creates their message boards or file areas and asks AreaFix or FileFix for all of them in one request.
  • File echoes. Files a network distributes arrive in a file area through its own moderation, each checked against its TIC: password, CRC and size. Echoes you don't carry wait for you instead of being lost. Hatch your own files into a file echo, and ask other nodes for files, or answer their requests, by name.
  • Polls and answers. NetBBS calls your hub on a schedule, and sooner when mail is waiting, over IPv6 or IPv4 and over TLS where the hub offers it. It can also answer calls on the BinkP port, 24554, speaking binkp/1.1.
  • Real-name echoes. On a message board that requires verified, displayed real names, posts go to the echo under each author's verified real name, for echoes such as nixNet's NIX_ADMIN.
  • Direct netmail. The nodelist imports itself when the network sends it, NODEDIFFs included, and netmail goes straight to any node that lists a BinkP host. Everything else goes through your hub.

For callers

An echo is read like any other message board, and netmail is written like any other letter.

  • Names with addresses. Authors from the network show as Joe Bloggs (21:3/110), and Reply works as usual.
  • Netmail from Mail. Write Name (zone:net/node) on the To line. The compose screen says that netmail is not private.
  • The SysOp decides who sends. Netmail leaves under the node's address, so only the SysOp can send it until the SysOp lowers its level.
  • Files, crash and hold. The SysOp's netmail can carry files and go out crash or hold, and netmail for nobody here goes back to its sender.
  • Offline with QWK. Callers can download their unread mail as a QWK packet, answer it in a reader such as MultiMail, and upload the replies.

Since 22 October 2026 ReLink has been a node on nixNet, polling its hub, posting echomail and linking echoes with AreaFix. File echoes and the automatic nodelist are new in v7.36 and have not met a live hub yet. New in v7.39: a node can serve its own points and downlinks as a hub, publish a pointlist and a nodelist segment, and join or serve QWK networks such as DOVE-Net. None of these has met another system yet. New in v7.40: a new network starts from a template for fsxNet, nixNet or FidoNet. The SysOp handbook has the setup steps; QWK networks have their own QWKnet chapter.

NetBBS Link

Independent communities, connected.

Independent nodes find each other and share message boards, chat channels, mail, and file catalogues. You choose what your node carries and who it trusts. NetBBS Link is a separate setup choice; project-operated reliable nodes help with discovery and relay. Federation remains private and experimental while real-world validation continues. A standalone node is a complete BBS.

  • Signed node identity. Every peer is a cryptographic keypair, not a hostname you have to trust blindly.
  • Trust that's earned, not assumed. Reputation and vouching decide how much a linked node's content is worth to you — and every decision is visible and overridable by a SysOp.
  • Trust that runs on its own. New nodes and callers can graduate from probation without a SysOp once they have been in contact on three separate days, a node seen signing two conflicting histories is reported with a signed accusation others can check, and a key compromise reaches even nodes that know its owner only by introduction.
  • Real-time, across nodes. Live chat channels stay live over NetBBS Link in both directions, not just asynchronous mail and post sync, and a caller can invite someone on another BBS to a direct chat.
  • Moderated together. A node can let people on other BBSes moderate what it shares: their post edits and removals, mutes, bans and topics reach every node that carries it, and a linked message board or chat channel can be handed to another node.
  • Reachable behind NAT. Automatic relay selection means even an outgoing-only node can still be found, live traffic can tunnel through an HTTP proxy, and verified ages and names reach it sealed for that node alone.

What's inside

The essentials of a community BBS.

Conversations, files, games, and practical controls for the people who run them.

Message boards & file areas

Message boards with a post list and a reader, polls, posting to several message boards at once, full-text search, browser file transfers, and Zmodem for compatible terminal clients.

Real-time chat

Chat channels with scrollback, private messages and direct chats, also with callers on linked BBSes, moderation, live presence, a bell that rings your terminal when someone messages you, and /sysop to page the SysOp. At logon, a oneliner wall keeps a short line from each caller for the ones after them.

Inter-BBS chat

Bridge chat channels onto the MRC network, or let callers open any room on it as a chat channel.

Chat bots

Baud ships with NetBBS: greetings, reminders after a delay or at a time, notes for someone’s next visit, dice, quotes and quick polls, last-seen and node statistics, door game results, and new-post announcements, each switched on by the SysOp per chat channel. Callers can ask a bot privately, and a bot can answer with a titled block. Any program can be a bot through the open bot API, with a one-file developer kit, and the SysOp can try a bot on a scratch node before callers meet it.

FidoNet & fsxNet

Echomail on your message boards and netmail in Mail, over BinkP that NetBBS speaks itself, with a nodelist for direct netmail.

Personal mail

Mail with drafts, replies, forwarding, several recipients, read receipts and blocking — local, or across NetBBS Link with delivery you can see.

Communities

Group related message boards, chat channels, and file areas under one topic-first roof, and share a whole Community with other nodes over NetBBS Link.

Trust & moderation

Mute/ban/kick, approval queues, permission grants, moderators on other nodes for what you share over NetBBS Link, and identity attestation.

Make it yours

Your own ANSI art as the welcome banner, or as the main menu and message board, file area and chat channel lists themselves, playing at a modem's speed if you like; art from scene tools shows as drawn; and node-wide branding colors.

SysOp tooling

User, message board and file area management, a Levels screen that shows what each access level opens, automatic promotion under rules you set, staff permissions for helpers who are not SysOps, a welcome letter for every new account, a queue of pages from callers, announcements a chat channel hears on a schedule, scheduled backups, installing a new release, the node log, an audit log, and graceful shutdown.

Built to run modestly

NetBSD-first and pkgsrc-friendly, comfortable on hardware you already own.

Doors & games

Three bundled games, plus profiles for trusted native, DOSBox-X, remote services such as DoorParty and BBSLink, and per-caller virtual-machine doors. A door can report game results for Baud to announce in chat.

Get started

Start with a local look around.

This is a trial on your own machine: only you can connect to it. A node that callers can reach is a permanent installation with its own service account, which the SysOp handbook walks through. The trial database can simply be deleted afterwards.

You need Python 3.11 or newer: python3 --version tells you which you have. On Debian and Ubuntu, also run sudo apt install python3-venv first. Download the .whl file (the “wheel”, a ready-to-install package) from GitHub Releases into a fresh directory. In the commands below, replace VERSION with the version number from the file you downloaded: for netbbs-7.40.0-py3-none-any.whl that is 7.40.0. The newest release is always at the top of the Releases page.

shell 
# install the downloaded release in a private environment (.venv)
# [ssh,web] adds SSH callers, browser callers and NetBBS Link: keep it
python3 -m venv .venv && . .venv/bin/activate
python -m pip install "./netbbs-VERSION-py3-none-any.whl[ssh,web]"

# create yourself as SysOp; setup then opens the SysOp console: [B]ack leaves it
python -m netbbs.admin --db netbbs.db
python -m netbbs --db netbbs.db --ssh-host 127.0.0.1 --disable-link

Setup asks for your username and a password or key, then two questions: whether to join NetBBS Link, the network of other nodes, and whether to take a free yourname.netbbs.org address. Answer no to both for this trial; both default to yes, so read before pressing Enter. --disable-link keeps the trial off NetBBS Link even if you said yes by accident. You can say yes on your permanent node. Once the node is running, from another terminal, run ssh -p 2222 yourname@localhost using the account you created. On NetBSD, install the SSH build prerequisites from the handbook first. For source development, see the developer handbook.
