Run a BBS you actually own

NetBBS is a modern build of the dial-up bulletin board — message boards, real-time chat, mail, and file areas — reachable over Telnet, SSH, or a plain browser. No client to install, no platform holding your community hostage. Put your chat rooms on MRC, the inter-BBS network other boards already talk on, run the DOS door games your callers grew up with, and mesh your node with NetBBS Link — an ad-hoc peer network with no central server anywhere in the middle.

Getting in

Three ways in. Zero client software.

Callers connect however is convenient for them — nothing to download, nothing to configure beyond a hostname.

Telnet

The classic path — any terminal, any telnet client, on the port you choose.

SSH

Key or password auth over an encrypted channel — the transport most operators reach for by default.

Web

A real terminal in the browser via xterm.js — send a link, they're in. No app, no extension.

New in v7.2

Both bundled games look like games again.

NetBBS ships two of its own door games, and until this release both of them were a wall of grey sentences — not because nobody styled them, but because the one function every screen's rows passed through on the way to the terminal stripped the colour back off again. That is fixed, and both games were rebuilt on top of the fix.

Voidrunner — a cockpit, not a spreadsheet

A persistent deep-space trading career: routes, contracts, cargo, faction standing, and a ship that takes damage and has to be repaired. Every screen now reads as an instrument panel.

  • Gauges on one scale. Hull, fuel and hold share a twenty-cell bar beside the ship's own silhouette, so one glance says what is wrong.
  • The market is a table. Seven columns where there were seven sentences, and a sparkline putting the quote in front of you against that commodity's price in all five economy types.
  • Alerts carry the key that answers them. A critical hull is red with [Y] repair; contraband aboard is amber with [D] jettison.
  • Motion you can switch off. Screens reveal as you arrive at them and hull bars drain when a shot lands — and a new Full palette, no motion preset turns every bit of it off.

War Dialer — a phosphor terminal

Run a crew across a ten-exchange network: case a target, pick an approach, take it before a rival does, and keep your Heat under the level that gets you busted.

  • The ring is the map. Ten exchanges drawn with their real links and coloured by who holds them — the same colour on the ring, in the table and in the feed, because one function decides it.
  • Every gauge means something. Cash, Heat, crew, turns and holdings across the top, over a rank ladder with your own rung lit.
  • A number is an exchange, not a row. Press a digit for its own card: owner, defence, your odds as a bar, the capture price and its neighbour discount.
  • Motion strictly after the commit. A result is in the database before the first frame is drawn, and any key skips the rest of it.

Both games ship with the node and need nothing installed. Classic DOS doors remain the separate case: NetBBS supplies the integration, not the software — those need legally obtained game copies, a FOSSIL driver and a socket-ownership-fixed DOSBox-X build installed on the host by you. The door setup guide has the build patches, the tested matrix and the checks to run.

NetBBS Link

An ad-hoc mesh, not a platform.

Independent nodes find each other and share message boards, chat channels, mail, and files directly — no central server, no registry, no company in the middle deciding what stays up. NetBBS Link is opt-in and off by default; a node that never enables it is a complete BBS on its own.

  • Signed node identity. Every peer is a cryptographic keypair, not a hostname you have to trust blindly.
  • Trust that's earned, not assumed. Reputation and vouching decide how much a linked node's content is worth to you — and every decision is visible and overridable by a SysOp.
  • Real-time, across nodes. Live chat channels stay live over NetBBS Link, not just asynchronous mail and post sync.
  • Reachable behind NAT. Automatic relay selection means even an outgoing-only node can still be found.

What's inside

A genuinely full-featured board, not a toy.

Everything a caller or a SysOp expects from a real community server, built for the modern network instead of a modem bank.

Message boards & file areas

Paginated message boards, full-text search, and real Zmodem uploads/downloads.

Real-time chat

Chat channels with scrollback, private messages, moderation, and live presence.

Inter-BBS chat

Personal mail

Asynchronous mail, local or addressed across NetBBS Link — separate from live chat.

Communities

Group related message boards, chat channels, and file areas under one topic-first roof.

Trust & moderation

A custom welcome banner, main-menu masthead, and node-wide branding colors.

SysOp tooling

User, message board and file area management, backups, an audit log, and graceful shutdown.

Built to run modestly

NetBSD-first and pkgsrc-friendly, comfortable on hardware you already own.

Doors & games

Native, DOS-under-DOSBox-X and remote doors in one menu — plus two bundled games of its own.

Try it now

A real node, running in about two minutes.

This is the fast, from-source path to look around. For a persistent node other people actually connect to, the operator guide covers the complete install.

shell 
# clone and set up
git clone https://github.com/Thiesi/NetBBS.git
cd NetBBS
python3 -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"

# create yourself as SysOp (prompts for username/password), then start the node
python -m netbbs.admin --db netbbs.db
python -m netbbs --db netbbs.db --enable-telnet

Then, from another terminal: telnet localhost 2323, log in, and look around — you're a SysOp on your own node. Ready for something persistent? See the operator guide on GitHub for the complete install-through-running path.
