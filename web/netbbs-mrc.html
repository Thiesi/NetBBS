Multi Relay Chat · built in

MRC, spoken natively.

NetBBS connects to Multi Relay Chat, the public inter-BBS chat network that Mystic, Synchronet and ENiGMA½ boards use, with nothing extra to install. The bridge runs inside the node and speaks MRC's wire protocol directly: no gateway program, no door, no separate client. MRC rooms show up as ordinary NetBBS chat channels.

For callers

Same chat, more people.

A bridged chat channel looks and works like any other chat channel on the node. It has the same line editor, scrollback, search and moderation. The only difference is who is in the room: callers on other boards, wherever they connected from.

For SysOps

Switched on from the console, watched live.

The hub link is off until the SysOp turns it on. Settings apply live: saving reconnects the bridge without restarting the node. Which chat channels are bridged is decided per chat channel, so turning MRC on never puts a chat channel on the network by itself.

Ground rules

A public network, handled carefully.

MRC is unauthenticated and has one central hub. NetBBS treats everything that arrives from it accordingly.

Nothing is bridged by accident

  • Off by default. The SysOp enables the hub link, then maps each chat channel to a room by hand.
  • Open rooms are a separate switch, with a minimum caller level, a cap, a retention period and a blocklist.

Remote authors stay remote

  • Never a local account. Every inbound line is shown as an external, unverifiable author, with control and escape sequences stripped.
  • Kept apart from NetBBS Link. A room a caller opened is never shared over NetBBS Link in either direction.

Private things stay private

  • No stored MRC credentials. Registration and identify commands read the password with echo off and send it once; it reaches no scrollback, log or input history.
  • Private messages are opt-in and unstored, with a plain warning that a public hub can read or spoof them.

Bounded, whatever the hub does

  • Rate-limited both ways. A fixed outbound queue and per-caller limits mean a stalled hub or a pasting caller only quiets the bridge.
  • Reconnects on its own, with backoff, and re-announces exactly who is in each bridged room.
